# Week 17 Part B: Agentic Assistant MLOps

This project carries the W15 customer-support assistant forward, adds the W16 evidence-aware agent loop, and applies this week's MLOps work to compare agent configurations. The default implementation is local and deterministic; no API credentials are needed for training, evaluation, the UI, or tests.

## What is included

- W15 production boundary: FastAPI `/chat` API, structured responses, request IDs, input validation, rate limiting, Streamlit UI, and Docker Compose.
- W16 agent behavior: retrieval, relevance checks, a bounded refined search, source-grounded answers, and clarification when evidence is weak.
- MLOps: three agent configurations evaluated on the same labeled queries, MLflow tracking and exported comparison artifacts, plus an Evidently HTML drift report.
- Reproducibility: `pyproject.toml` and `uv.lock`.

## Environment and run

From this folder, install uv if needed and synchronize the lockfile:

```powershell
uv sync
.\.venv\Scripts\Activate.ps1
```

Run the configuration comparison and generate the reports:

```powershell
uv run python -m mlops.evaluate
```

Outputs:

- `reports/agent_configuration_comparison.csv`: summary metrics for fast, balanced, and thorough configurations.
- `reports/agent_query_evaluations.csv`: per-query outcomes, selected actions, confidence, and trajectory length.
- `reports/evidently_agent_configuration_drift.html`: Evidently comparison of baseline and selected configuration telemetry.
- `mlruns/`: local MLflow experiment runs and per-run evaluation JSON artifacts. This local tracking store is regenerated by the command and is not committed.

The evaluation reports task success, expected-route accuracy, safe clarification rate, valid tool-action rate, average trajectory length, and an approximate context-word count. The word count is only a local proxy; it is not billed LLM token usage. `fast`, `balanced`, and `thorough` vary retrieval top-k, evidence threshold, and maximum iterations. All configurations use the same evaluation cases for a fair comparison.

## MLflow UI

In a second terminal, from this folder:

```powershell
$env:MLFLOW_ALLOW_FILE_STORE = "true"
uv run mlflow ui --backend-store-uri .\mlruns --host 127.0.0.1 --port 5000
```

Open `http://127.0.0.1:5000` and inspect the `part-b-agent-configuration-comparison` experiment. The CSV comparison table and query-level JSON are also logged in the experiment runs.

## Run the assistant

Start the API:

```powershell
uv run uvicorn app.main:app --reload
```

Start the UI from another terminal:

```powershell
uv run streamlit run ui.py
```

Open `http://localhost:8501`. The API health endpoint is `http://localhost:8000/health`; interactive docs are at `http://localhost:8000/docs`.

The default `LLM_PROVIDER=none` uses the local support knowledge base. To enable the optional OpenAI-compatible response refinement, install `uv sync --extra llm`, set `LLM_PROVIDER=openai`, and provide `OPENAI_API_KEY` through an environment variable. Never commit API keys.

Agent behavior can be adjusted using `MAX_ITERATIONS` (1-8), `RETRIEVAL_TOP_K` (1-10), and `MIN_EVIDENCE_SCORE` (0-1). Defaults are conservative and the retrieval loop is always bounded.

## Docker

```powershell
docker compose up --build
```

The Streamlit UI is at `http://localhost:8501`; the API is at `http://localhost:8000`. Compose defaults to local deterministic mode.

## Tests

```powershell
uv run pytest -q
```

## Data and limitations

The support knowledge base is a small curated set of generic banking-support articles from the W15/W16 project. The experiment cases are a deterministic evaluation suite, not customer data. Results compare the configured agent behavior on this fixed suite and should not be interpreted as production traffic performance. Evidently monitors evaluation telemetry drift; it does not replace monitoring on a live production request stream.
